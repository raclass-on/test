# 초등 영문법 자체 개발 프로젝트 — 기획안

> 레이첼영어학원 · 2026-08-16 초안
> 목표: 클래스카드 의존(월 40만원)을 단계적으로 걷어내고, 학원 소유의 문법 훈련 시스템을 구축한다.

## 1. 배경과 목표

- 현재 클래스카드 이용료 **월 약 40만원 (연 480만원)** 지출 중. 용도는 ① 초등문법훈련 드릴 ② 단어장 학습.
- 1차 목표: **문법 파트를 100% 자체 개발**하여 문법 용도의 어플 의존 제거 → 요금제 축소.
- 2차 목표: 문법 앱이 안정화되면 **단어장 기능도 자체 앱으로 이전** → 클래스카드 완전 대체.
- 대체 후 운영비: 웹 호스팅 무료 티어(Vercel/Netlify) 기준 **월 0~2만원 수준**.

### 저작권 원칙
클래스카드 교재는 **구성 방식(5단계 훈련 사이클)만 참고**한다. 문법 목차 자체는 표준 초등 영문법 범위(공유 재산)이며, 문항·예문·해설·캐릭터 대사는 **전량 신규 창작**한다. 원문 문장을 복사·변형하지 않는다.

## 2. 제품 구성 (무엇을 만드는가)

| 구성물 | 내용 |
|---|---|
| **문항 데이터** | 유닛당 5단계(개념톡→Check→Practice→Upgrade→Master) JSON. 앱과 지면 인쇄 양쪽에서 사용 |
| **학생용 웹앱** | 유닛 선택 → 단계별 풀이 → 즉시 채점 → 점수 → 오답노트(틀린 문항 재풀이) |
| **교사용 대시보드** | 학생별 점수·진도, 유닛별 정답률, 리포트 |
| **지면 출력(선택)** | 같은 JSON에서 인쇄용 워크시트 생성 — 태블릿 없는 수업 대비 |

콘텐츠(JSON)와 앱을 분리하는 것이 핵심 설계다. 문항은 데이터일 뿐이므로, 앱을 고치지 않고도 유닛을 계속 추가할 수 있고, 나중에 단어장 모듈도 같은 앱에 얹는다.

### 유닛당 문항 구성 (클래스카드 분석 기반)

| 단계 | 문항 수 | 유형 | 학습 목표 |
|---|---|---|---|
| 개념톡 | 대화 1편 | 대화형 설명 + 중간 빈칸/미니퀴즈 | 개념 인지 |
| Check | 18~20 | 고르기, 찾기, O/X, 연결하기 | 식별 (인지) |
| Practice | 16~18 | 2지선다 → 우리말 보고 단어 쓰기 | 반산출 |
| Upgrade | 10~12 | 빈칸 쓰기 + 단어 배열 | 문장 구성 |
| Master | 10 | 우리말 보고 문장 전체 쓰기 | 완전 산출 |

- 유닛당 약 **55~60문항**, 같은 핵심 문장 재료가 단계를 올라가며 반복 등장하도록 설계.
- 전체 규모: **69유닛 × 약 57문항 ≈ 3,900문항**.

## 4. 팀 구성 (AI 에이전트 팀)

총괄(PM)은 메인 세션이 맡고, 실제 제작은 역할별 에이전트를 병렬로 띄워 진행한다.

| 역할 | 인원(에이전트) | 담당 |
|---|---|---|
| **총괄 PM** | 1 (메인) | 배치 계획, 품질 기준, 최종 병합·커밋 |
| **문항 제작** | 유닛당 1 (배치당 4~8 병렬) | 담당 유닛의 개념톡 + 5단계 문항 전체를 JSON으로 제작 |
| **교차 검수** | 문항 제작과 별도 2~3 | ① 문법·정답 오류 ② 난이도·어휘 수준(초등 어휘 범위) ③ 유닛 간 중복 문장 검사. 제작자와 다른 에이전트가 "틀린 곳을 찾아라" 관점으로 검수 |
| **스키마 QA** | 스크립트 자동화 | JSON 스키마 검증 + 정답 키 무결성(모든 문항에 정답 존재, 배열 문제의 정답이 실제로 조합 가능한지) 자동 체크 |
| **앱 개발** | 1~2 | 학생용 풀이 화면, 채점 로직, 오답노트, 교사 대시보드 |

검수를 통과하지 못한 유닛은 제작 에이전트에게 반려 → 수정 → 재검수. **원장님 최종 검토는 배치 단위**로 받는다 (파일럿 배치는 전수 검토, 이후 배치는 샘플 검토).

## 5. 작업 분할 — 배치 계획

- **배치 단위 = 챕터.** 챕터가 학습 단위이자 검수 단위로 가장 자연스럽다. 유닛 수가 2~8개로 편차가 있으므로 작은 챕터는 2개씩 묶는다.
- **한 배치 = 유닛 6~8개 (문항 350~450개)** 를 표준으로 한다. 이보다 크면 검수 품질이 떨어지고, 작으면 배치 오버헤드가 커진다.

| 배치 | 챕터 | 유닛 수 | 비고 |
|---|---|---|---|
| **B1 (파일럿)** | Ch01 명사 + Ch02 관사 | 8 | 문항 톤·난이도 기준 확립. 원장님 전수 검토 |
| B2 | Ch03 대명사 + Ch05 There+be | 8 | |
| B3 | Ch04 be동사 | 6 | 파일럿 피드백 반영 후 첫 정규 배치 |
| B4 | Ch06 일반동사 | 8 | 최대 챕터 |
| B5 | Ch07 진행형 + Ch08 미래형 | 7 | |
| B6 | Ch09 형용사 + Ch10 부사 + Ch15 비교 | 7 | |
| B7 | Ch11 조동사 + Ch12 전치사 | 8 | |
| B8 | Ch13 의문사 + Ch14 문장의 종류 | 6 | |
| B9 | Ch16 접속사 + Ch17 to부정사 | 6 | |
| B10 | Ch18 동명사 + Ch19 품사 총정리 | 5 | |

- 속도: 제작+교차검수+수정까지 **주 1~2배치**가 현실적 페이스. 전체 콘텐츠 완성까지 **약 6~10주**.
- 앱 개발은 콘텐츠와 병행: 파일럿 기간에 MVP를 만들고, 이후 배치가 추가될 때마다 데이터만 얹는다.

## 6. 1차 파일럿 (지금 시작하는 범위)

**범위: 배치 B1 = Ch01 명사(6유닛) + Ch02 관사(2유닛), 총 8유닛 약 450문항 + 웹앱 MVP**

산출물:
1. **문항 JSON 8유닛** — 신규 창작, 교차 검수 완료본
2. **웹앱 MVP** — 유닛 선택 → Check/Practice/Upgrade/Master 풀이(고르기·O/X·빈칸 쓰기·단어 배열·문장 쓰기 5가지 입력 방식) → 즉시 채점 → 점수 화면 → 오답노트 재풀이. 학생 이름 입력만으로 시작(로그인 없음), 결과는 브라우저 저장 + 교사 확인용 결과 코드
3. **개념톡 열람 화면** — 대화형 개념 페이지 (음원은 후순위, 우선 텍스트)

파일럿 성공 기준:
- 원장님 검토에서 문항 오류율 기준 통과 (수정 요청 10% 이하)
- 실제 학생 1개 반이 태블릿/폰으로 유닛 1개를 끝까지 풀고 점수·오답노트가 정상 동작
- "이 정도면 클래스카드 대신 쓸 수 있다"는 판단

**파일럿에서 확정하는 것**: 문항 톤(반말/존댓말), 캐릭터 설정, 난이도 곡선, 어휘 통제 범위, 지면 인쇄 필요 여부. 이 기준이 B2 이후 전 배치에 적용되므로 파일럿 검토가 가장 중요하다.

## 7. 앱 기능 명세

### MVP (파일럿)
- 학생: 이름 입력 → 유닛 선택 → 단계별 풀이 → 자동 채점 → 점수/정답률 → 오답노트(틀린 문항만 재출제)
- 문항 렌더러: 선택형, O/X, 연결하기, 빈칸 타이핑, 단어 배열(터치), 문장 쓰기 — 6종
- 교사: 결과 열람(학생별 점수·오답 목록)

### 2단계 (정규 운영)
- 반/학생 관리, 숙제 배정, 기간별 리포트
- 스펠링 채점 관대화 옵션(대소문자·구두점), 음원(TTS)
- 지면 워크시트 PDF 생성

### 3단계 (단어장 모듈 — 클래스카드 완전 대체)
- 현재 저장소에 있는 단어 학습 앱 프로토타입(FlashCard·Quiz·WordList·Progress)을 같은 앱 안의 모듈로 통합
- 단어 세트 업로드 → 플래시카드 / 리콜 테스트 / 스펠링 / 매칭 게임 → 망각곡선 기반 복습 큐
- 클래스카드에서 실제로 쓰는 기능 목록을 먼저 뽑아 필수 기능부터 이식

## 8. 데이터 스키마 (요약)

```json
{
  "unitId": "u001",
  "chapter": 1,
  "title": "명사의 의미와 종류",
  "conceptTalk": [
    { "speaker": "teacher", "text": "...", "blank": null },
    { "speaker": "quiz", "question": "...", "options": ["..."], "answer": 0 }
  ],
  "stages": {
    "check":    [ { "type": "choice|ox|match|find", "q": "...", "options": [], "answer": "...", "hint": "..." } ],
    "practice": [ { "type": "choice2|write", "q": "...", "ko": "...", "answer": "..." } ],
    "upgrade":  [ { "type": "write|arrange", "ko": "...", "tokens": [], "answer": "..." } ],
    "master":   [ { "type": "compose", "ko": "...", "answerTokens": [], "answer": "..." } ]
  }
}
```

정확한 스키마는 파일럿 시작 시 `docs/schema/` 에 JSON Schema로 확정하고, 모든 배치는 자동 검증을 통과해야 병합한다.

## 10. 기대 효과

- 문법 파트 자체화만으로도 요금제 축소분 절감, 완전 대체 시 **연 약 480만원 → 호스팅 0~24만원**.
- 문항·앱이 학원 자산으로 남아 커스터마이징 자유 (우리 학원 시험 유형 반영, 중등 문법으로 확장 등).
- 리딩 교재(라클라스)와 함께 자체 콘텐츠 라인 완성.
